# HQPlayer 独立播放模组（实验版 0.2.4）

仅使用主程序的 `playback.backends` 实验接口；不修改主程序安装文件、不依赖 Native Audio 模组，不捆绑或重新分发 HQPlayer。0.2.3 的流式功能需要提供 `supportsStreams` 的新版宿主统一媒体桥；旧宿主仍使用完整文件暂存。HQPlayer 负责解码、滤波、升频、调制和音频设备输出，Folia 负责曲目、播放队列和歌词时间轴。

## 安装与使用

1. 使用本仓库 `personal/playback-backends` 自维护分支构建的 Folia，它保留 `playback.backends` 接口；官方主线的 mpv 后端不等于具备该模组接口。原上游 PR #844 已关闭，本分支独立维护。
2. 自行安装 HQPlayer Desktop，在 HQPlayer 中允许网络控制，关闭其 Settings 对话框。0.1.3 默认在选择此后端时自动启动尚未运行的 Windows Desktop，已运行则直接连接、不重复启动；仅启用模组不会启动。当前模组仅连接本机 `127.0.0.1:4321`，可自定义端口，不关闭 HQPlayer，不支持远程实例。
3. 在 HQPlayer 配置实际输出设备，启用可变音量，并设足够低的最小音量（建议至少 -100 dB）。固定/旁路音量会被拒绝；模组不擅自修改这些设置。滤波、升频和输出模式可继续在 HQPlayer 配置，也可使用下述 DSP 草稿。
4. Folia 设置 → 模组中导入 `hqplayer-0.2.4.zip`，确认权限并启用。执行“检查 HQPlayer 连接与注册状态”，结果会显示在命令卡和提示中，不展示注册人、指纹或注册码。这个诊断命令仍为只读，不自动启动程序。
5. Folia 设置 → 播放 → 播放后端，选择 `HQPlayer Desktop (local)`。选择只在本次 Folia 运行有效；启用模组不会自动接管输出。
6. 默认要求 HQPlayer 已停止且当前曲目列表为空。若确需接管其他播放，先在 HQPlayer 自行保存列表，再在模组设置主动打开“允许替换 HQPlayer 已有播放列表”。模组会切换正在使用的 URI 传输，不提供自动恢复。

修改连接设置会暂停并重新准备当前曲目，不自动恢复发声。DSP 草稿独立于连接设置，编辑草稿不会重建传输或发送设置命令。HQPlayer 的设备、独占、CUDA、多核等仍在 HQPlayer 设置，不再叠加 Native Audio 或宿主 DSP。

## 0.2.4 恢复进度确认

修复重新打开流音源后从头发声、界面却保留旧进度的问题：`Seek result=OK` 只表示指令被接收，不代表解码器已经跳转。准备期间暂存的跳转在 URI 加载后先暂停输出，等待有效时长，再发送整数秒 Seek 并读取原生位置确认；尚未生效时有界重试（最多三次、总等待约八秒），确认后才继续播放。失败保持暂停并保留待恢复位置，不假装成功或静默从头重播，不放宽外部接管和音量保护。

宿主 `0.7.22-personal.0.8` 同时修复了恢复结束时强行写入目标进度的问题，必须收到当前位置附近的实际 playing 回报才恢复歌词 / 进度时钟，失败会暂停并报错。此次需要同时更新宿主和本模组；旧模组不能仅靠安装新宿主获得原生 seek 确认。HTTP 容器或服务器不支持跳转时仍可能无法续播，此时明确保持暂停，不承诺任意流音源都可 seek。

## 0.2.2 后台心跳与手动恢复

渲染窗口心跳中断超过 15 秒时，模组清理自己的输出，并通知宿主暂停和显示错误，不再让界面停留在“播放中”。心跳恢复不会自动发声；下一次明确按播放时，先等待旧输出清理成功，再重新准备保留的音源、恢复最后确认的位置并播放。超时后暂停、拖进度都不会重新启动输出；拖动的位置会用于下一次播放。清理失败时拒绝重新打开输出，需先确认 HQPlayer 已停止，再重新加载模组。

桌面歌词、透明窗口及 Windows 壁纸切换的后端选择与进度交接由修订后的宿主负责：只保留用户明确选中的任意模组后端，旧输出清理完成后才重建窗口，恢复后保持暂停。仅升级本模组不能修复旧宿主的窗口交接遗漏。未选中 HQPlayer 时，不接管其他后端。

## 0.2.1 临时提前停止策略

按用户要求新增“提前停止暂按正常结束处理”，**默认开启**，在模组设置和“配置 HQPlayer 连接”命令中均可调整。仅当本模组已开始播放、仍拥有该传输，且 HQPlayer 明确返回 STOPPED 时，即使最后确认进度离结尾较远，也发一次结束事件，由 Folia 按当前队列 / 循环模式继续。日志保留最后确认进度、时长及停止时的进度、时长和曲目数，不记录 URI 或凭据。它是兼容绕行，不证明真正播放完毕，也没有修复 HQPlayer 最初为何停止。

暂停、静音、DSP 应用、主动清理时不触发队列前进；STOPREQ 仍等待真正停止并受原有超时限制，断连 / 状态读取失败 / 外部接管仍按错误处理。HQPlayer 中手动停止本模组的曲目也可能被当作结束；需要停播请在 Folia 暂停。若设备持续导致停止，开启此策略可能连续跳过曲目，应关闭开关排查。

关闭兼容开关后，提前停止仍报错，但修正了错误后无法恢复的两个逻辑问题：已被 HQPlayer 清空的 URI 不再被标成“已加载”，再次明确按播放时用 PlayNextURI 重新加载并恢复最后确认的整数秒进度；客户端错误终态仅在明确播放时重置，恢复后时钟能够继续更新。不会自行重播，不放宽外部接管或音量保护。真实 EOF 保留同一个可核对 track_id 的单曲传输时，也允许继续切歌，不再误认为他人接管。

现场日志中 16:52 的提前停止与随后 16:55 的 `Opening source failed: network error` 是不同阶段：前者来自模组状态判断，后者发生在宿主下载 / 暂存音源阶段、进入模组 open 之前。本版不改主程序，也不声称解决后一个下载问题。日志若包含 Cookie 或临时播放地址，请脱敏后再公开。

## 模组内 DSP 设置

1. 在模组卡片或命令面板执行“读取 / 刷新 HQPlayer DSP 选项”。此操作只读、不启动 HQPlayer，用实时设置覆盖未应用的旧草稿。
2. 编辑新出现的“HQPlayer DSP 草稿”：Nx 升频滤波器、1x 基础采样率滤波器（协议有返回时）、抖动 / 噪声整形 / 调制器、输出采样率。选项全部来自当前实例；“跟随音源 / 自动”仅在 HQPlayer 提供该选项时出现，不保证固定输出到某个频率。
3. 执行“应用 HQPlayer DSP 草稿”才生效。会先检查选项是否过期；本模组正在播放时，停止自己的 URI 输出并保留整数秒进度，不自动恢复，需手动按播放。不会停止其他控制器的播放；外部播放未停止或列表非空时拒绝设置。无变化时不发送任何设置或停止命令。
4. 模式通过独立的“切换 HQPlayer 输出模式”命令应用；应用后重新读取依赖该模式的滤波器、整形器、采样率，请再次检查草稿。PCM/SDM 等仅显示当前设备 / HQPlayer 实际公布的模式，不能凭此解锁硬件或软件不支持的模式。

修改连接设置、命令失败或选项过期后需重新读取。刷新会丢弃未应用草稿；启用模组、换歌、下次启动都不会自动套用 DSP 草稿。协议没有设置事务，部分命令成功后断线时不自动重试或猜测回滚，而是提示重新读取并核对当前配置。

不通过修改 `settings.xml` 接管设备、独占、CUDA、多核、授权等配置。没有提供所谓“最佳听感”一键预设；更重的滤波或更高采样率不必然更好，也可能超出机器处理能力。

## 0.2.0 连续播放控制修复

修正将 `STOPREQ`（停止中，可能临时清空曲目和时钟）误判为外部控制器接管的问题；自然结束经过此状态时保留末尾有效时钟，最终正确发出结束事件。持续停止中超过 10 秒会有界报错。暂停仅发送一次切换命令，再等待实际确认，避免异步暂停被过早判失败。已经验证且仍打开的控制连接跨曲目复用，不再每首歌额外探测和重新查询 GetInfo。

这些状态机错误已有旧逻辑失败 / 修复后通过的回归证据；旧 0.1.5 包和新包在本机均能通过短程连续播放，尚未稳定复现用户现场“约两首后失控”，不能认定已定位唯一原因，更不能由等待线程数推断已确认死锁或内存耗尽。更新只涉及模组，无需重新安装主程序。

自动启动可在模组设置关闭；程序路径留空时读取 Windows 安装信息（支持 Desktop 6/5），也可填写 `HQPlayer6Desktop.exe` 或 `HQPlayer5Desktop.exe` 的完整路径，不接受命令行参数。已运行但未开启网络控制时，只等待接口就绪并在超时后提示，不另开实例。并发的后端选择/准备请求共用串行启动检查，不会反复启动。自动启动不改变音量、设备、滤波、授权或网络控制设置，也不会自行开始播放。

0.1.5 修复自动启动时隐藏 HQPlayer 窗口的问题：Desktop 按正常可见方式启动，安装信息查询的 PowerShell 辅助窗口仍隐藏。此修复只影响之后的新进程；升级不会自动显示、关闭或重启旧版本已启动的隐藏实例。需在停止播放后自行退出旧实例，再由新版模组启动，无需更新主程序。

## 音量与静音

Folia 的线性音量转换为 HQPlayer 的 dB 衰减。100% 不超过模组上限（默认 -6 dB，最多 -3 dB），也不超过接管时 HQPlayer 本来的音量；换曲不会重复累计衰减。不能接受请求音量时暂停并报错，不向上钳制成更响的音量。

**0%/静音通过暂停 HQPlayer 保证无声**，不是普通的“静音但时钟继续走”；解除静音后保持暂停，需重新按播放。固定音量被拒绝是有意的安全限制，不能通过关闭报错来忽略宿主静音。

## 输入与状态

0.2.3 默认开启“通过 Folia 流式播放在线音频”，也能在“配置 HQPlayer 连接”命令中调整；开关在下次加载曲目时生效。新版宿主的统一鉴权媒体 bridge 把已解析的 HTTP(S) 或已登记媒体协议转成按需读取的本机随机令牌地址，模组直接用该地址调用 `PlayNextURI`，无需先等全曲下载。不访问 QQ、网易云、酷狗等平台的登录接口，不读取账号 Cookie，不接收原始签名播放 URL；各平台仍由宿主 Omni/provider 负责鉴权和音质。宿主不会给任意媒体 URL 附带登录 Cookie；需要专用鉴权的音源由宿主媒体协议处理。Range、HEAD、背压与取流故障在宿主处理，模组无额外监听端口，不重编码，不叠加 Web Audio。

关闭流式开关、使用旧宿主，或者读取完整缓存 Blob / 本地文件时，仍由宿主暂存原始字节；模组识别容器并复制为带正确后缀的私有文件交给 HQPlayer。此兼容路径仍有 512 MiB 上限。未知容器、HQPlayer 不支持的编码不会转换或回退浏览器。流式起播、拖动及恢复取决于上游服务、签名有效期、网络和 HQPlayer；直播、DRM 或所有平台/格式的真实兼容性未经验证。

0.1.2 起使用官方 `PlayNextURI(value=<本机路径或宿主流地址>, freewheel=0)` 开始新曲目，暂停后用 `Play(last=0)` 恢复。不再调用 `PlaylistAdd`、`SetTransport` 或 `PlaylistClear`：本机实测旧的 `PlaylistAdd` 链路会导致 HQPlayer 退出，而 `PlayNextURI` 可以播放同一份 WAV。准备曲目不会调用 `PlayNextURI`；首次播放时才启动音频，并等待曲目数/播放状态就绪。准备期间的跳转暂存到实际加载后执行。

周期查询状态最多 2 Hz，时钟使用协议的秒单位；seek 精度为官方接口的整数秒，命令确认后时钟可能稍后才更新。状态码依据官方 SDK：0 停止、1 暂停、2 播放、3 正在停止。URI 传输停止/结束时曲目数可能变为 0；这不等于被其他控制器接管。0.2.1 默认把已开始播放的本模组传输的明确停止当作结束；关闭临时兼容开关后，只有接近已知曲目结尾的停止才触发队列前进。

**0.1.4 的字幕回跳修复完全在模组中，无需更新此前交付的后端改造版主程序。** 客户端的 `displayClock.mjs` 去掉重复/小幅回退的位置回报，按旧宿主的一秒外推规则生成连续锚点，防止状态回调与帧循环反复拉扯。前向校准每次最多 20 毫秒；超出允许领先范围时暂缓回报，让宿主已有的外推上限冻结并等待 HQPlayer 追上，避免持续累积漂移。没有增加查询、定时器、RAF 或逐帧 RPC，不访问主程序的私有对象。

暂停和停止依据 HQPlayer 实际位置重新对齐；明确跳转立即显示整数秒目标，命令期间不接受排队的旧进度，收到确认后恢复。如果目标迟迟没有被状态确认，3 秒后的新状态会重新对齐实际位置，不让字幕永久卡在目标。切歌/重配置会重建锚点，错误和结束后忽略迟到的播放状态；单曲循环允许重新跳回开头。未知/重复进度或断连时，不凭空生成持续播放进度。精度仍受 HQPlayer 状态粒度和传输延迟限制，不承诺采样级字幕同步。

HQPlayer 的实际采样率、模式、位数和滤波器可通过检查命令查看。此控制协议不能证明 WASAPI/ASIO 独占成功，因此不向宿主伪报“已确认独占”或“共享输出”，不承诺 bit-perfect 或更高采样率必然改善听感。

切换后端或禁用模组时，停止本模组拥有的 URI 传输，不清空 HQPlayer 原有播放列表、不关闭 HQPlayer。检测到其他控制器接管后不停止对方。渲染进程失联 15 秒后尝试停止。正常退出也会发起清理，但宿主不等待模组异步退出，网络命令可能被截断；Folia 退出、被强杀、HQPlayer 断线或清理失败时都无法保证外部播放器已停止，请在 HQPlayer 中确认。不要同时使用多个控制器修改同一 HQPlayer 播放内容。控制端口仅用于本机可信进程；不会绕过 HQPlayer 的授权、认证或试用限制。

Windows 上 HQPlayer 报告停止后仍可能保留解码文件句柄。旧曲目的私有缓存等新 URI 加载后再删除；仅 `EBUSY` 文件占用会记录警告并延后清理，其他错误仍然报出。最后一个被占用的文件可能留在模组缓存中，可在 HQPlayer 关闭后清理缓存；不会为删除缓存强制退出 HQPlayer。

## 构建与验证

0.2.4：410 项宿主 / 模组 / 归档 / 遥控相关测试、类型检查及模组静态检查通过。新增宿主 → 实际客户端 / 字幕时钟 → 实际引擎的断流恢复测试，检查原生位置而非只检查是否调用 seek；覆盖首次 Seek ACK 被忽略、元数据迟到、跳转不支持时保持暂停，以及取消恢复。实际 ZIP 的 TCP 模拟器也加入了忽略首次 Seek 的恢复回归；未操作用户当前运行的 HQPlayer 或真实账号，不能把模拟器通过视为所有真实流媒体都已验证。

0.2.3：262 项宿主 / 模组 / 更新 / 分层相关测试和类型检查通过；模拟慢速源验证首块在 EOF 前可读取，覆盖 Range、HEAD、令牌归属 / 撤销、错误阻止误跳歌、旧宿主完整暂存及日志脱敏。实际 ZIP 的 TCP 模拟器验证宿主流 URI、暂停 / seek、静音与连续五轮换曲。这里没有连接真实平台账号或控制用户正在运行的 HQPlayer，不等于所有平台、格式及真实 DAC 的流式播放已验证。

断连错误会标出等待响应的命令名，不输出曲目 URI 或凭据；不会自动重试播放命令。0.1.1 仅补齐字段，真实测试仍在 `PlaylistAdd` 处失败，因此使用 0.1.2 的 URI 传输链路，不建议继续用旧包。

如果 HQPlayer 在开始播放时退出，先不要反复从 Folia 重试。保存列表、调低硬件音量后，可以手动将同一首本地文件直接加入 HQPlayer 对照；若直接播放也退出，优先查 HQPlayer 自身、输出驱动和处理配置。若只有模组触发退出，记录错误中的命令名、退出时间和 Windows Application Error/Windows Error Reporting 记录。历史记录的程序路径和时间不匹配时，不能据此给本次退出定因。模组不修改许可证、调试/注入环境或 HQPlayer 安装文件。
