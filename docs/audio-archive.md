# 已播放音频归档（个人版）

桌面端「设置 → 存储与备份 → 已播放音频归档」。先选择应用、用户数据与缓存目录之外的文件夹，再开启「自动归档完整音频」；默认关闭，更换目录也会关闭采集。仅保存你有权归档的音源，不绕过 DRM、试听或平台访问限制。

## 保存与播放

- 第一版采集经过宿主 HTTP bridge 的模组后端音频，例如开启流式的 HQPlayer。保存收到的编码音频，不录制设备输出、不重编码，也不是 HQPlayer 升频后的 PCM/SDM。浏览器直接网络播放、旧宿主完整暂存和平台专用分段协议当前不采集。
- 目录是 `平台 / 歌单名 [来源标识摘要] / 歌手 - 歌名 [实际音质-歌曲标识摘要].实际扩展名`。歌单取自当前队列的明确来源，在加载音源时快照；搜索、混合队列和未知来源放在 `Unsorted`。文件名清理 Windows 保留名、非法字符与结尾空格。同名歌曲不靠名字判断身份。
- 只有实际开始播放、收到完整文件并通过容器和时长检查后才发布。无需听到最后一秒，但纯预取不发布；`ended`（含 HQPlayer 的提前停止兼容策略）不是完整性证据。
- 播放后端在有效 `playing` 状态上报的进度达到歌曲标示时长的 80% 后，保留本次采集任务。已有完整文件直接保存；不完整时等待当前读取结束，再按字节覆盖表用 `Range` / `If-Range` 补缺口。切歌撤销播放地址不会取消该任务，已写入的前缀与中间区间不重复下载。这里是播放位置，不是累计收听时长；跳转到 80% 后继续播放也会触发。
- 「优先播放本地归档」默认开启。播放与预取在请求平台音频 URL 之前查找同一平台、歌曲及音质的索引，核对文件大小及 SHA-256。命中后通过不可猜测、随主窗口生命周期撤销的本机协议供各后端读取，支持 HEAD/Range，不向模组暴露磁盘路径。
- 音质不匹配、文件丢失、校验失败或明确的故障恢复跳过归档，照原流程取源；不会删除损坏文件、自动降级归档音质或自动重播。平台曲目信息、歌词和账号相关请求仍可能访问网络。关闭本地优先后，之前预取到的旧归档地址也不代替新取源。
- 普通媒体缓存和归档互相独立。清理缓存不删归档；应用不自动清理归档，你需要管理磁盘空间。

## 完整性与边界

每曲最大 512 MiB。仅收集有明确长度的 200/206 响应。Range 按文件偏移写入并合并覆盖区间；跨响应必须有相同的强 ETag 和总长度，没有校验标识只接受一次覆盖完整文件的响应。中断读取的已写字节只有在强 ETag 可核对时才复用。补齐必须返回完全匹配的 206 范围、版本和长度；忽略 Range、文件版本变化、鉴权过期或网络失败时放弃补齐，不重新获取平台 URL、不重下整首、不发布缺尾文件。HEAD、未知长度和传输压缩不作为完整文件发布。

完整字节还要识别为支持的音频容器，元数据解析出的时长至少达到歌曲标示时长的 90%；无法确认、试听或短片段跳过。临时文件在 `.folia-partials`，索引在 `.folia-index`，都在所选根目录。正常撤销时清理本次未完成数据；强杀或断电可能留下 `.part`，它们不会被当作歌曲播放。

采集观察器异步写盘，待写队列每曲最多 8 MiB、同时最多八个采集会话（含切歌后补齐）。积压或写入失败放弃本次归档，不让播放器等待磁盘。后台补齐每曲串行请求，最多 64 个缺口、首次补齐请求起两分钟内完成。关闭归档、更换目录、主窗口导航/崩溃/销毁或退出应用会取消后台任务并清理临时文件。不跨应用重启续传 `.part`，不把不同源地址的内容合在一起。

## 实现入口

- `electron/audioArchive/`：边界校验、采集、文件安全、索引、本机读取和受信任 IPC。
- `electron/playbackBackends/streams.cjs`、`electron/hifi/sourceBridge.cjs`：给已有字节转发接入可选观察器。
- `src/services/audioArchive/`：公开 DTO、状态和本地优先查询。
- `src/components/modal/settings/pages/storage/AudioArchiveGroup.tsx`：设置界面；命令面板提供设置入口与归档开关。

设置与归档仅保存在本机，不加入外观配置或跨设备同步。音源凭据仍归宿主管理，索引不含签名 URL、Cookie 或 Authorization。
