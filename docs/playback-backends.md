# 播放后端与独立模组

## 自维护分支与上游同步

`personal/playback-backends` 保留上游 mpv HiFi 和通用模组接口。统一入口在「播放控制 → 播放引擎」；`selection.ts` 先暂停并等待旧输出释放，再选择并准备新引擎，保留进度且不自动播放。主线 mpv 的来源限制、满音量确认和设备设置不变，显式选择模组时不再进入主线 mpv 路线。

主线信号链路面板只适用于 Web Audio / 内置 mpv，使用模组时隐藏该入口，不把外部播放器误标成 Web Audio 或已确认直通。模组输出的设备 / 格式以模组遥测和播放器自身显示为准；HQPlayer 的真实 SDM 输出仍需单独验证。

日常同步在这个长期分支上合并 `origin/main`（本地远程 `origin` 是上游，`fork` 是个人 GitHub 仓库），不强推或反复改写已发布历史。宿主适配与两个模组分别提交；合并前保留快照。重点回归引擎互斥、旧会话事件隔离、静音、暂停 / seek、连续结束换曲和歌词时钟；模拟测试不证明真实 DAC 的独占或 SDM 能力。本分支的检查更新固定到个人发布源，不消费官方包；首次启用、版本标识和发布流程见 [个人版更新](personal-updates.md)。

宿主改造入口是 `src/services/playbackBackend/`，不依赖具体引擎。Folium 边界在 `src/mods/folium/playbackBackends.ts`；模组声明 `playback.backend` 权限和 `playback.backends` 实验 opt-in 后，在主窗口通过 `folium.experimental['playback.backends'].register` 注册。完整结构类型来自 `contract.ts`，编辑后运行 `npm run folium:types` / `npm run folium:api`，不手改生成文件。

契约：`create(report)` 创建会话，`open` 准备暂停输出，`play/pause/seek/setVolume/dispose` 操作它；事件带每次加载唯一的 `sourceId`。实际输出遥测将 `exclusiveRequested` 与 `exclusiveActive` 分开；模组应依据设备确认，而不是照抄开关。宿主过滤退休会话/音源的事件，序列化准备与清理，使用原生时钟驱动既有 MotionValue 帧循环。

状态通知可以同步触发准备下一首或自动播放，因此宿主先发布会话重建 / 音源加载的等待任务，再通知观察者；切歌经过空音源时，下一首必须等旧输出清理和新会话创建完成。初始化或清理失败保留原始错误，不改报为笼统的后端不可用，也不绕过失败清理新建输出。

注册不等于启用后端。用户在播放控制中显式选择；默认保持 Web Audio，选择不持久化。选中模组被撤销时暂停并保留“不可用”选择，不能偷偷换输出。外部输出期间不挂浏览器音源，并旁路宿主 EQ、ReplayGain、automix 与淡入淡出。切换输出会暂停，释放前一个设备后才允许新会话初始化。

内部窗口重建（透明 / 桌面歌词 / Windows 壁纸模式）会在短期 handoff 中保存已选后端 ID，并读取该后端的进度；这不等于普通启动时自动选中模组。旧输出清理成功后才允许重建，恢复时保持暂停。选中的模组迟到或缺失时保留不可用选择，不回退到 Web Audio；用户仍可明确选择其他输出。遥控窗打开期间暂停主窗口后台节流，避免状态发布与模组心跳被限速。

支持 HTTP 的后端使用统一的鉴权媒体 bridge：Omni 按歌曲来源取得当前账号可用的音源，主进程持有签名地址，并通过 Electron 网络栈或已注册的媒体协议按需转发原始字节。普通 URL 请求显式省略 Cookie；需要平台专用鉴权的音源应由宿主已登记的媒体协议处理。模组只接收 `source.url` 中的随机令牌本机地址，不接收平台 URL、Cookie 或登录凭据，不直接调用平台 API。`supportsStreams` 表明宿主支持此能力，`capabilities.http` 在每次准备音源时读取，后端可据此提供流式开关。这里统一的是媒体访问能力，各平台的登录、会员权限和音质解析仍由现有 provider 实现，不另建混合 Cookie 仓库。

桥复用 `electron/hifi/sourceBridge.cjs`，仅监听 `127.0.0.1`，按需传输并处理背压；转发 GET / HEAD 和 Range，不向下游传递 Cookie、重定向地址或上游认证头。令牌按主窗口归属，切歌、释放、页面导航、崩溃或退出时撤销并中断传输；不接受任意文件路径或未登记的私有协议。

当前源码将远程传输实现在 `electron/hifi/remoteSource/`。正常响应缺少 Range 声明时，先用 `bytes=0-0` 核对 206、Content-Range、总长度和资源版本，再在 GET / HEAD 中提供 `Accept-Ranges: bytes`；探测最多两秒、不会进入下载速度或归档统计。完整、合法的 206 也能提供范围能力证据。不能验证时不照抄上游的 bytes 声明；同一强 ETag / 长度的验证结果在租约内复用。首次请求可能增加一次极小的网络往返。

已有响应遇到可恢复的上游断流时，优先保持下游 HTTP 响应，让解码器等待原输入。已知字节长度、无 HTTP 内容压缩且存在强 ETag 时，从第一处未转发的字节发送 Range / If-Range，严格核对 206、起止偏移、总长度和版本，再继续原响应；不重开播放器、不插入静音、不裁切或重编码音频。上游忽略 Range、版本改变或偏移不符立即拒绝拼接。读取超时为 15 秒，续传重连窗口为 60 秒，等待下游 drain / 暂停读取不计作网络超时；撤销租约取消读取、探测和退避。不具备安全拼接条件或重试耗尽时才关闭下游并保留故障原因。归档观察器按每段实际响应记账，同一版本的前后段可合并。

支持 seek 的 HTTP 模组在原生输出实际停止、且伴随明确的网络断流（包括连接重置、超时、响应截断、HTTP 408/429/5xx）时，宿主冻结上一次有效进度并等待，不当作 EOF 跳歌；仍能播放缓冲数据时不提前冻结或重开。主进程以同一音源地址做 `Range: bytes=0-0` 就绪探测，单次最多 8 秒，重试间隔 1/2/4/8 秒后最多 10 秒，直到恢复或用户取消。探测只读首块便取消，不强制下载整曲；成功后通过模组契约重新打开音源、seek 到原进度，再按当前播放意图继续。暂停取消自动恢复，再次播放才重新等待；切歌、切换后端和窗口退休使旧恢复任务失效。不重启 HQPlayer，不改设备、DSP 或音量设置（恢复时仅重发宿主已设置的播放音量）。

从 `0.7.22-personal.0.8` 起，恢复完成必须收到新传输在目标附近的实际 playing 状态（允许整数秒量化及已流逝时间），不再把请求的 seek 位置直接写成正在播放。只收到 loading / paused 或零点回报时继续等待确认，最多八秒；失败暂停输出并报错。暂停、切歌和换后端立即取消待确认任务。HQPlayer 配套模组 `0.2.4` 在暂停状态核对原生 seek，需同时更新；旧模组可能无法完成原生恢复，但新宿主不会再用目标时钟掩盖它。

当前修订进一步要求目标附近的 playing 时钟实际推进（不是单个时间或重复的目标占位），非零续播还需新加载的输入证据：已验证可寻址，且真实读取了新的非零范围，或新输入已完整送达。旧请求、HEAD 和一字节就绪探测不算新续播证据；八秒内无法确认则暂停报错，不显示假成功。这个证据不映射压缩字节到播放秒数，也不证明可听输出已达到采样级定位；仍保留原生 Seek、sourceId 隔离和受限时钟外推，不另建独立播放时钟。网络故障序号区分旧错误和恢复中新发生的断流，旧错误不把新的设备 / seek 失败变成无限重试。

401/403/404、拒绝的媒体类型、无效音频，以及未伴随明确音源网络故障的设备、授权和控制连接错误仍报错，不盲目重试；不支持 seek 的模组和文件暂存路线保持原行为。签名地址过期不会绕过 Omni 重新获取授权，需正常重载曲目。恢复网络不保证后端或容器允许准确 seek。

遥控小窗口通过原有 500 ms 快照显示缓冲转圈及音频下载速度，在控件淡出和只显示模式中也可见。网速统计媒体桥实际转发的原始音频字节，采用最近两秒平均值，停止接收后归零；不包含恢复探测、歌词、封面或独立归档补齐流量，不表示音频码率，也不进行重新编码。已观察到的非恢复性取流故障仍将 ended 转成 error；仍有重试中断流时，其他小请求或就绪探测不能清掉它的故障。

文件型后端和已经完整缓存的 Blob 仍通过 `playbackSources.stage` 暂存原始字节（不经过浏览器解码），上限 512 MiB；这条兼容路径仍需等完整读取。在线地址过期、平台限流、容器兼容、是否支持 Range 和 HQPlayer 初始化耗时不因 bridge 消失，不保证每个平台/格式都能立即起播。模组安装容许原生引擎，ZIP 最大 128 MiB、单文件 128 MiB、展开总量 256 MiB、文件数 2000，解压和内容摘要仍执行上限与路径校验。

独立实现放在 `extensions/native-audio/`，不在官方签名示例 `mods/` 中。源码与可安装 ZIP 分开；引擎下载、校验、离线 SoXR 探针、运行库与许可打包由模组自身的 `package.mjs` 负责，不往宿主塞播放器或 DSP 实现。

## HQPlayer 独立模组

`extensions/hqplayer/` 通过同一契约实现 Signalyst Control API，本机程序发现、按需启动和传输逻辑都留在模组里，无须给宿主增加 HQPlayer 分支。使用限制和验证记录见模组 README。官方 [Embedded 产品页](https://signalyst.com/hqplayer-embedded/) 与 [下载 / SDK 入口](https://signalyst.com/downloads/) 是接入依据。

0.1.4 的 `extensions/hqplayer/displayClock.mjs` 在模组客户端去重重复位置，并按旧宿主的一秒插值规则回报连续时间，避免原始状态把字幕时钟拉回。小幅前向校准有单次上限；领先过多时暂缓回报，让旧宿主停止外推并等待原生时钟追上。明确 seek、暂停、切歌与错误单独处理。不增加 HQPlayer 查询频率、定时器或逐帧 RPC，不访问宿主私有状态，也不需要修改或重新安装已有支持播放后端接口的主程序。

适配时仍需处理服务发现/认证、版本能力、播放时钟/seek、错误和断线恢复。远端 HQPlayer 不能读取 Folia 的 blob 或本机暂存路径，需后续设计可访问的媒体服务及访问控制，不能把本地路径直接交给远端。HQPlayer 自己负责滤波/设备输出，宿主不替它宣称独占或 bit-perfect，也不未经用户选择同时启用两条 DSP 链。
